ERA V5 · Session 7 · Problem 5

Making the Kronecker embedding run backwards

The Kronecker codec is exactly invertible, so the output head can be replaced by the input projection transposed. That removes the output matrix entirely and unties model size from vocabulary size — at a measured cost, reported here rather than rounded off.

The idea in one paragraph

A token is a byte string. The codec writes it as a sum over byte positions, κ(b) = (1/√L) Σp cbp ⊗ pp, which lands in a fixed space of D = 256 × 32 = 8192 dimensions regardless of how many tokens exist. Because the byte and the position occupy separate axes, nothing is mixed: coordinate b·32 + p means “byte b sits at position p” and nothing else. So the map is invertible, and the output side can be a classifier over that same grid instead of a softmax over a vocabulary.

Try it

The grid is 32 × 256: one row per byte position, one column per byte value. Exactly one cell is lit per row. Decoding reads each row's argmax and stops at the first PAD — which is why any byte string is reachable, not just the ones in a vocabulary.

What was measured

The held-out vocabulary test

Comparing heads on ordinary text only shows whether the byte head keeps up. The actual claim of P5 is vocabulary-freedom, so a set of token ids was withheld from every arm's training loss. Those tokens still appear in the context, so every arm's shared input pathway sees their bytes; no arm is ever trained to predict them. They are then scored on exactly those positions.

One prediction at a time

The same test, asked more bluntly: not “was the token right” but “how close was the byte string”. Both measures are defined for every arm — whatever token the baseline picks is a byte string too — so this is not a metric the byte head grades itself on.

Why not nearest neighbour?

The session's framing is to predict the Kronecker vector and look up the closest token. Two measurements, one of which came out against the design argument and is reported anyway.
