I ran the full 8-stage cleaning pipeline for real on Common Crawl — the web-crawl repository this session is built around. I chose it over a curated dataset because curated data is already clean; this is the genuine pre-cleaning web, so the losses are real. 128 million words of raw web enter on the left; 17 million survive. The two biggest cuts are exactly where the session shows they'll be: Language ID (the web is 111 languages — we keep a target set) and Quality filtering (the open web is mostly SEO spam, keyword-walls and boilerplate). Deduplication removes less here because near-duplicates are a global phenomenon spread across the whole crawl — a single slice only holds a fraction of each duplicate cluster, exactly the point Widget 6 makes about local-vs-global dedup.
Comparison · the same pipeline on two corpora

Raw web vs a curated archive

To prove the point, I ran the identical 8-stage pipeline on both Common Crawl (raw web) and a slice of Indian Supreme Court judgments (multilingual, curated). Same code, same thresholds, same seed — and the outcomes are opposite: raw web loses 86.5%, the court archive loses just 9.4%. Curated corpora are the output of a cleaning pipeline; Common Crawl is the raw input.

Why this matters for the assignment: it's the concrete reason I chose Common Crawl as my dataset. A cleaning pipeline can only be demonstrated on data that is actually dirty. The court judgments barely move (Language ID keeps all 18 target languages; Quality passes real legal prose; Dedup finds one cluster) — so they can't show what the strategies do. Raw Common Crawl exercises every stage. Note the PII row: the court corpus flags 73,219 "phone numbers" — nearly all false positives on legal citation/case numbers, a reminder that PII regex must be tuned per domain.

Q2 · What dataset was picked

Common Crawl CC-MAIN-2025-13 (WET)

I picked Common Crawl — the open repository of web-crawl data the session centres on as the primary source. I deliberately did not use a curated HuggingFace dataset, because those are the output of a cleaning pipeline, so cleaning them again removes almost nothing (I verified this myself on Supreme Court judgments and on ai4bharat/Sangraha: ~94–98% retention). Only raw crawl data shows what cleaning actually does.
