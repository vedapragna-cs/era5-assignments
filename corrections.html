Corrections and limitations

The assignment asks us to check every date against a primary source, and to say so if the course material got something wrong. It also warns that our own agent will invent dates confidently. Both directions are recorded here, including one case where we went looking for an error and found the material was right.

correction C1

DroPE is an acronym collision, and the obvious match is the wrong paper

claim, and where it comes from
Our own first instinct, and what an exact-string search returns
what we checked
arXiv full-text search for 'DroPE', then both candidate abstracts via the arXiv API
finding
Two real papers share the acronym. DRoPE (arXiv 2503.15029, v1 2025-03-19) is 'Directional Rotary Position Embedding for Efficient Agent Interaction Modeling' — autonomous-driving trajectory generation, nothing to do with context extension. DroPE (arXiv 2512.12167, v1 2025-12-13) is 'Extending the Context of Pretrained LLMs by Dropping Their Positional Embeddings', which is the one the lesson means. The wrong paper is the better string match and is nine months earlier, so an agent that trusts exact-match ranking will report 2025-03-19 and then confidently describe a self-driving system.
what we did about it
Timeline uses 2025-12-13 (arXiv v1, API-confirmed). The collision is documented here rather than silently avoided.
primary sources
https://arxiv.org/abs/2512.12167
https://arxiv.org/abs/2503.15029
correction C2

The lesson says DroPE's mechanism is not established. It was published eight months before the lesson.

claim, and where it comes from
Lesson section 9, and widget s8_widget_8_drope — the two agree, so this is the course's settled position, not a prose slip
what we checked
The lesson's callout reads: 'What the available record does not establish: the exact DroPE algorithm or which rotary dimensions it changes. Any more detailed mechanism is a hypothesis until it is checked against the reference implementation.' The widget repeats it verbatim and states it 'deliberately does not simulate an unverified DroPE mechanism.'
finding
The mechanism is public. arXiv 2512.12167 (v1 2025-12-13, eight months before this lesson) states it in the abstract: positional embeddings are dropped entirely after pretraining, followed by a short recalibration phase. The paper's argument is that explicit position is a necessary convergence prior during pretraining but is precisely what blocks test-time generalisation to unseen lengths — so removing it beats scaling it. Note the direction of this correction: the question the lesson leaves open has a published answer, and the answer is more interesting than a rotary-dimension tweak, because DroPE is not a RoPE variant at all.
what we did about it
We state the mechanism and cite the paper. We flag the identification itself as inference: the lesson never names a paper, and the V4 cookbook line 'positional recalibration: DroPE, applied before annealing' matches the paper's recalibration phase closely but is not proof they are the same procedure.
primary sources
https://arxiv.org/abs/2512.12167
limitation C3

NTK-aware scaling has no paper and we could not pin its exact day

claim, and where it comes from
Our own chronology requirement
what we checked
reddit.com and old.reddit.com both return HTTP 403 from this environment, so the post's timestamp could not be read directly. Fell back to the YaRN bibliography and the GitHub API.
finding
NTK-aware scaled RoPE originated as a Reddit post by u/bloc97, cited as bloc97 [2023a] in YaRN's bibliography — and YaRN's first author, Bowen Peng, is u/bloc97, which makes that citation effectively primary. The bibliography gives the year only. Hard bounds from the GitHub API: github.com/jquesnelle/scaled-rope was created 2023-06-26T13:27:56Z, and bloc97's PR #1 ('NTK-Aware interpolation by parts correction') opened 2023-07-07T20:40:33Z.
what we did about it
Dated 2023-06-26 (bounded, not exact) and rendered as unverified on the timeline. The widely-repeated 2023-06-30 is plausible but we could not confirm it, so we do not assert it. Because the bound is eleven days wide, this card's ordering relative to Position Interpolation (2023-06-27) is inside the uncertainty band and we say so rather than implying a photo finish we cannot prove.
primary sources
https://github.com/jquesnelle/scaled-rope
https://arxiv.org/abs/2309.00071
observation C4

The lesson contains no dates at all

claim, and where it comes from
Lesson markdown, all 1,532 lines
what we checked
Regex for any four-digit year 19xx/20xx across the full lesson markdown pulled from /api/lessons/cms8lmsrhwu9k6b284dx.
finding
One match, and it is not a date: 2025 appears as a path component inside an image URL on line 40. Zero dates. The lesson teaches eighteen mechanisms and dates none of them. The assignment then makes chronology the graded axis and warns that dates are 'exactly where an AI agent can sound completely confident while being wrong'. (We first reported this as 'zero matches', which was wrong about the regex even though the conclusion held — corrected after review.)
what we did about it
This is consistent rather than contradictory — it means every date in this app had to come from a primary source, because there was no course-supplied number to copy or to check against. It also means the instructor cannot have made a date error in the lesson, which narrows where his 'if I have made one here, catch that too' can apply.

negative-control C6

We tried to break the lesson's KV-cache arithmetic and could not

claim, and where it comes from
Lesson section 10
what we checked
Recomputed 2 x layers x kv_heads x head_dim x T x bytes for the lesson's stated yardstick: 48 layers, 8 KV heads, head_dim 128, bf16, T = 32,768.
finding
2 x 48 x 8 x 128 x 32768 x 2 = 6,442,450,944 bytes = 6.442 GB decimal, which the lesson gives as 6.44 GB. Eight users: 51.54 GB, which the lesson gives as 51.54 GB. Both exact. The DroPE widget's 8K to 256K = 32x also checks out (262144 / 8192 = 32).
what we did about it
No correction. This is here deliberately: a conflict hunt that only ever finds conflicts is not a hunt, it is a bias. The lesson's arithmetic is right, and reporting that is the control on the five findings above.

correction C8

The assignment's minimum list omits two mechanisms the session taught

claim, and where it comes from
The assignment's 'What to cover, at minimum' list, in both the lesson (section 18) and the portal description
what we checked
Walked all 18 lesson sections against the 17-item list instead of treating the list as the specification, then counted term frequency across the lesson markdown.
finding
Two taught mechanisms are absent from the list. Section 13, 'Schedules across depth', teaches hybrid depth schedules — the DDDGDDDG motif of six DeltaNet fixed-state layers to two sparse-attention layers, held from a 1.78B seed to a 120B run. Section 14, 'State that outlives the window', teaches cross-chunk O(1) state: the V4 Memory Stream, one model-width vector written with stop-gradient and read through a learned gate. Frequency check: schedule appears 10 times in the lesson and Memory Stream 4 times, against one occurrence each for ALiBi, MLA and attention sinks — all three of which the list does name.
what we did about it
Both are on the timeline with primary-source dates, and the cross-chunk lineage the lesson leaves implicit is supplied: Transformer-XL (2019-01-09) for segment-level recurrence, Compressive Transformer (2019-11-13), and RMT (2022-07-14) as the closest published relative of the Memory Stream. This is offered as a gap in the list, not an error in the teaching — the sessions are consistent; the enumeration is just shorter than the lesson.

self-correction C9

Two rounds of independent review falsified our headline finding and sixteen other claims

claim, and where it comes from
Our own published work, at commit a6bf322
what we checked
We commissioned three independent reviews — one re-fetching every date from the arXiv API without trusting our own verification script, one grading the rendered HTML against the assignment text, one auditing the technical accuracy of every mechanism description against the source papers.
finding
They found real defects, and we had missed all of them. The headline finding (Q2-1) claimed the publish-to-ship lag "collapsed from 3.5 years to zero" — but the column mixed third-party adoption with authors' own same-day code drops, so the collapse was substantially an artefact of switching definitions; two of its dates were also wrong. Nine further errors: GQA's group arithmetic (32 query heads over 8 KV heads is 8 groups, not 4); Position Interpolation's "32x" (the abstract says 32,768 tokens, which from LLaMA's 2,048 is 16x); FlashAttention described as "bit-for-bit" exact (tiling reorders floating-point accumulation, so it is mathematically exact but not bit-identical); Differential Transformer costed at "double the score computation" (the paper halves head count precisely to stay FLOP-matched); a fabricated lineage claiming Differential Transformer descends from the attention-sink diagnosis (2410.05258 never cites StreamingLLM and never uses the word 'sink'); Q2-7's claim that ALiBi's and RoPE's authors did not know each other's work (ALiBi benchmarks against rotary explicitly); MLA's 93.3% described as versus a dense baseline (DeepSeek 67B already used GQA); Transformer-XL credited with "no extra training memory"; and Q2-9 grading a pair "ambiguous" by failing to apply its own stated rule — which, applied correctly, makes the instructor right. A second round found more: the Transformer-XL fix had never been applied though this entry claimed it was; the Memory Stream card was silently dropped from the rendered page by an era-bucket bug while the build still reported 34 cards validated; the DSA card described a low-rank block-selecting indexer when DeepSeek published a token-selecting lightning indexer (C11); MQA's shipped row used Falcon-40B when SantaCoder is 18 months earlier; MLA's 93.3% turned out to include 6-bit KV quantization, with architecture alone accounting for about 82 points; and five shipped rows violated the very rule the first retraction had promised to apply uniformly.
what we did about it
All corrected in place, with retractions visible rather than the text quietly swapped. Including one correction that did not take: the Transformer-XL memory fix was listed here as done and had in fact never been applied — the second review caught the log claiming a fix that was not in the artifact, which is worse than the original error. It is fixed now. Q2-1 has been rewritten twice; the current version applies one release rule to every row, which moved five rows once we found the authors had shipped code before their own papers. The lag chart was rebuilt as a sorted comparison because plotting lag against time implied a trend the data does not contain.
transcript-error C10

The transcript's "GSA" and "MSA" in the assignment sentence itself

claim, and where it comes from
S8 transcript, line 408 — the sentence where the instructor sets the assignment
what we checked
The transcript reads: "So you would cover Delta Knight, you will cover GSA, GQA, then you have MSA and whatever terms I'm using, right?" Checked each token against the lesson's own vocabulary.
finding
"Delta Knight" is DeltaNet, "GSA" is almost certainly GQA said twice, and "MSA" is either MHA or MLA — the lesson teaches both and neither is spelled MSA anywhere in it. The speaker's own hedge, "whatever terms I'm using", indicates he knew the names were approximate in speech.
what we did about it
Read as ASR artifacts, consistent with the same transcript rendering 2017 as "2018 and 17". We cover DeltaNet, GQA, MHA and MLA regardless, so nothing turns on the resolution. Recorded because we audited five other transcript conflicts and skipping this one — inside the assignment sentence itself — would have been selective.
correction C11

The lesson's "low-rank indexer" ranking "block summaries" is not what DeepSeek published

claim, and where it comes from
Lesson section 12: "DeepSeek uses a small low-rank indexer to rank the block summaries cheaply. The indexer does not produce the final attention output."
what we checked
DeepSeek's own tech report for V3.2-Exp, released with the weights on 2025-09-29.
finding
Three differences. DeepSeek calls it a lightning indexer; the string "low-rank" appears nowhere in the report. It selects individual tokens — the top-2048 key-value entries per query — not blocks, and the release explicitly contrasts this with block-granularity approaches, describing it as fine-grained sparse attention. And training is a dense warm-up stage followed by a sparse stage, not an interleaving of compressed-dense and top-k forms. The lesson's one-sentence summary that the indexer never produces attention output is correct and matches the report.
what we did about it
The card describes what DeepSeek published, and says so. This is a source-precedence case: the project rule ranks primary sources above lesson prose, and here they genuinely disagree on mechanism rather than on a number. Reported because we wrote the card from the lesson first and an independent review caught it — the same failure mode we documented in C9.
