How attention works now

Every attention mechanism from ERA V5 Session 8, in the order it was launched — not the order it was taught, and not grouped by family. 34 mechanisms, covering all 17 items on the required list plus 13 we added — 2 of which the session taught but the list omits. Each one is an answer to a problem that existed on its date, with what it buys, what it costs, and when you would pick it.

Start here: what everything else modifies

Nothing below makes sense without this. Scaled dot-product attention takes a query for the current token, scores it against the key of every token it is allowed to see, turns those scores into weights that sum to one, and returns the weighted sum of the values.

Q × K⊤
   ↓
 scores        one number per (query, key) pair — this matrix is the compute bill
   ↓
 scale         divide by √dₖ, or softmax saturates at high dimension
   ↓
 mask          a token may not attend to its own future
   ↓
 softmax       scores become weights that sum to 1
   ↓
 ∑ wV         weighted sum of values — the output

It sends two separate bills, and the whole timeline is people paying one of them down. Compute is the score matrix: n×n per head per layer, so doubling the context quadruples it. Memory is the KV cache at decode time: every token you have already generated leaves its keys and values behind, reloaded for every new token, growing linearly with length and with the number of concurrent users. Sparsity and linear attention attack the first bill. MQA, GQA and MLA attack the second. Position encoding is a third problem entirely — and, as the timeline shows, it arrived on the same day as the architecture.

How to read the dates

Sorted by arXiv v1 submission date — when the idea became public, not when it was published in a venue and not when it became popular. Where a mechanism shipped in a well-known model at a materially different time, that shipped date is shown too. The gap between the two turns out to be the most interesting column on the page; see what the timeline shows. One mechanism — NTK-aware scaling — has no paper at all and its exact day could not be verified; it and 2 others are marked date bounded, not exact rather than guessed.

The assignment predicts what this timeline will show — “exact global attention, cheaper decoding memory, better position handling, longer contexts, recurrent state returning, sparsity returning, compression becoming more aggressive.” We treated that as a testable claim and checked it against the dates. Most of it holds in order; one pair is inverted by 25 months.

Order stays chronological.

2014-2016 — attention before the Transformer

Additive attention (Bahdanau)

2014-09-01foundationadded — not on the required list
the problem at that moment
Sequence-to-sequence translation squeezed an entire source sentence into one fixed-length vector. Long sentences degraded badly, because the vector had no more room for the fiftieth word than the fifth.
mechanism
Let the decoder compute a weighted sum over all encoder states at every output step, with weights from a small feed-forward network scoring (decoder state, encoder state) pairs.
what it buys
Removes the fixed-length bottleneck. Translation quality stops falling off with sentence length.
what it gives up
Cost becomes O(n*m) in source and target length instead of O(n). The scoring network is an extra set of parameters trained per model, and it is sequential: the RNN still has to run step by step.
when you would actually pick it
Historical. You would not build this today, but every mechanism after it is a variation on the weighted sum it introduced.
Why this card is here. Not in the required list, and it belongs at the very start: attention predates the Transformer by two years and nine months. Opening the timeline in 2017 would imply the weighted sum was invented there. It was not — what 2017 added was dropping the RNN around it.
Date source: arXiv v1, confirmed via arXiv API
https://arxiv.org/abs/1409.0473

Multiplicative / dot-product attention (Luong)

2015-08-17foundationadded — not on the required list
the problem at that moment
Bahdanau's scoring network was a trained MLP evaluated for every source-target pair. That is a lot of small matrix work for what is conceptually a similarity.
mechanism
Replace the scoring MLP with a plain dot product between decoder and encoder states (optionally with a learned matrix in between).
what it buys
The score becomes a single matmul, which hardware is extremely good at. No extra scoring parameters in the simplest form.
what it gives up
Dot products grow with vector dimension, so the scores can get large and push softmax into saturation. The paper does not yet fix this.
when you would actually pick it
Historical, but this is the exact operation Session 2's scaled dot-product attention inherits. The scaling factor added two years later exists to patch the flaw this card introduces.
answers / builds on
End-To-End Memory Networks (arXiv 1503.08895) — softmax over inner products, five months earlier (2015-03-31); Bahdanau additive attention (2014-09-01)
Why this card is here. Not in the required list. It belongs immediately before the Transformer because this is where the score becomes a dot product — the exact operation Session 2 teaches. The sqrt(d_k) divisor in the standard formula is a patch on a flaw this card introduces.
Date source: arXiv v1, confirmed via arXiv API
https://arxiv.org/abs/1508.04025

Absolute learned position embeddings

2016-11-07position
the problem at that moment
A weighted sum over positions is order-blind: shuffle the input and the output is unchanged. Convolutional and attentional encoders both needed position put back in by hand.
mechanism
Keep a trainable lookup table with one vector per absolute position, and add it to the token embedding.
what it buys
Maximum flexibility: the model learns whatever positional structure the data actually has, with no assumption baked in.
what it gives up
The table has a fixed number of rows. Position 4097 in a 4096-row table does not exist, so the model cannot run one token past its trained length. Positions that were rare in training get undertrained rows.
when you would actually pick it
Short, fixed-length inputs where you will never need to extrapolate — classification heads, fixed-size encoders. Every long-context method on this timeline exists because this card's ceiling is hard.
Why this card is here. This predates *Attention Is All You Need* by seven months. We moved this date during review. It first sat at ConvS2S (1705.03122, 2017-05-08), the paper usually cited for learned absolute positions — but that card's own antecedent line named an earlier Gehring paper that already used them, and on a page whose thesis is that the date is the argument, citing the famous instance over the first one is exactly the error we are trying to avoid.
Date source: arXiv v1 (Gehring et al., A Convolutional Encoder Model for Neural Machine Translation), confirmed via arXiv API
https://arxiv.org/abs/1611.02344

2017 — the architecture, and the bill it created

Scaled dot-product attention

2017-06-12foundation
the problem at that moment
Attention still rode on top of a recurrent encoder, so training could not be parallelised across sequence positions. And Luong's raw dot products saturated softmax at high dimension.
mechanism
Q x K^T, divide by sqrt(d_k), mask, softmax, multiply by V. Drop the RNN entirely and stack this with feed-forward layers. Multiple heads run the whole thing in parallel subspaces.
what it buys
Every position attends to every other in one parallel operation. Training parallelises across the sequence, which is what made scale possible at all. The sqrt(d_k) divisor keeps softmax out of saturation.
what it gives up
Two separate bills. Compute is O(n^2 d) for the score matrix. Memory at decode time is the KV cache, which grows linearly with sequence length and with batch size, and never shrinks. Everything below is somebody paying one of these two bills down.
when you would actually pick it
Always the baseline, and still correct for short contexts. Below about 2K tokens the quadratic term is not what hurts you.
answers / builds on
Luong dot-product attention (2015-08-17); Bahdanau additive attention (2014-09-01)
numbers
O(n^2 d) compute, O(n) cache per layer per sequence — stated, lesson section 3, 'The two bills attention sends'
Date source: arXiv v1, confirmed via arXiv API
https://arxiv.org/abs/1706.03762

Sinusoidal position encoding

2017-06-12position
the problem at that moment
A learned position table cannot produce a vector for a position it never saw in training.
mechanism
Compute the position vector from a fixed formula: sines and cosines at geometrically spaced frequencies. No parameters at all.
what it buys
Defined at every position, including ones never trained on. Free in parameters. Neighbouring positions get similar encodings, and offsets are expressible as linear functions of the encoding.
what it gives up
Defined is not the same as useful. The model still only learned to interpret the frequency patterns it actually met during training, so quality degrades past trained length even though the formula keeps returning numbers. It is also added to the input once, so the positional signal has to survive every layer.
when you would actually pick it
When you want extrapolation to at least be defined and you do not want positional parameters. Superseded in practice by RoPE, which injects position at every attention layer rather than once at the input.
answers / builds on
Absolute learned positions (2016-11-07)
Why this card is here. Same paper, same day, as standard attention. On a date-sorted timeline these two are one event, which is itself the point: the Transformer shipped its position problem and its position patch simultaneously, and the patch was the weaker half.
Date source: arXiv v1, same paper as scaled dot-product attention
https://arxiv.org/abs/1706.03762

2019-2020 — the first wave: stop computing every pair

Segment-level recurrence (Transformer-XL)

2019-01-09recurrent stateadded — not on the required list
the problem at that moment
Train on long documents by cutting them into fixed-length segments and every segment starts cold. Context is destroyed at every boundary, and a token cannot see one position past the cut. This is context fragmentation.
mechanism
Cache the previous segment's hidden states and let the current segment attend to them, but write the cache under stop-gradient so the loss never back-propagates across the boundary. Relative position encoding is required to make the reused states meaningful at their new offsets.
what it buys
Dependencies that outlive the segment, roughly 4.5x longer effective dependency than a vanilla Transformer, and much faster evaluation because segments are not recomputed from scratch. Stop-gradient keeps the *backward* graph from crossing the boundary — but the cached hidden states are real activation memory at every layer, which is why how many segments you cache is a tuning knob.
what it gives up
Activation memory grows with how many segments you keep, so the context is bought with GPU memory rather than for free. Gradients stop at the boundary, so the model never learns to *write* a state that will be useful later — it only learns to read whatever happens to be there. The recurrence is also sequential across segments, which limits training parallelism.
when you would actually pick it
Any time you process a document in chunks and need something to cross the seam. This is the mechanism the course's Memory Stream is a compressed, O(1) descendant of.
answers / builds on
Scaled dot-product attention (2017-06-12)
Why this card is here. Not in the required list, and the one omission that most needed fixing: lesson section 14, 'State that outlives the window', teaches cross-chunk state with stop-gradient as V4's Memory Stream. This is that mechanism's dated public ancestor, stop-gradient and all, seven years earlier.
Date source: arXiv v1 (Dai et al., Transformer-XL), confirmed via arXiv API
https://arxiv.org/abs/1901.02860

Sparse attention (strided / fixed patterns)

2019-04-23sparsity
the problem at that moment
The n^2 score matrix became the binding constraint the moment anyone wanted images or long documents. At 16K tokens the matrix alone is 268M entries per head per layer.
mechanism
Do not compute every pair. Attend only along fixed patterns — a local band plus a strided set of columns — chosen so that any two positions are connected within two hops.
what it buys
Drops cost from O(n^2) to O(n*sqrt(n)). Made 16K-token sequences trainable in 2019 hardware budgets.
what it gives up
The pattern is fixed before you see the data, so a genuinely long-range dependency the pattern does not cover is unreachable in one layer. Child et al. do report their own sparse kernels beating dense on their benchmarks — the broader problem is that hand-written sparse kernels across the field generally ran below dense matmul efficiency, which is why dense attention stayed the default until FlashAttention made exactness cheap.
when you would actually pick it
When the sequence has known structure — images, audio, code with local scope — so a hand-chosen pattern is actually a good prior. This card is the origin of both sliding-window attention and every learned-sparsity method below.
answers / builds on
Scaled dot-product attention (2017-06-12)
numbers
O(n*sqrt(n)) attention cost — stated, Child et al. 2019, abstract
Date source: arXiv v1 (Child et al., Generating Long Sequences with Sparse Transformers), confirmed via arXiv API
https://arxiv.org/abs/1904.10509

Multi-query attention (MQA)

2019-11-06KV cacheshipped 2022-12-02
the problem at that moment
The second bill. At decode time you reload the entire KV cache for every single token you generate. That is memory bandwidth, not compute, and it is what actually limits tokens per second.
mechanism
Keep all the query heads, but give every head one shared key head and one shared value head instead of its own.
what it buys
Divides the KV cache by the number of heads — a 32-head model gets a 32x smaller cache, so decoding stops being bandwidth-starved and batch sizes can grow.
what it gives up
A quality cost. All heads must now agree on what to retrieve, which removes the representational diversity multi-head attention exists for. Shazeer characterises the degradation as minor — "only minor quality degradation"; the harsher reading, quality loss plus training instability, comes from the GQA paper four years later, which is also where the case for an intermediate point is made.
when you would actually pick it
Aggressive decode-throughput targets on a small model where you can afford the quality hit. Superseded by GQA, which recovers most of the quality for most of the saving.
answers / builds on
Scaled dot-product attention (its KV cache is the bill MQA attacks) (2017-06-12)
numbers
KV cache divided by the number of heads; "only minor quality degradation" — stated, Shazeer 2019, abstract
Why this card is here. Published November 2019 and then essentially unused for two and a half years. The idea was not waiting on insight; it was waiting on inference cost mattering enough for anyone to accept the quality hit.
Date source: arXiv v1 (Shazeer, Fast Transformer Decoding: One Write-Head is All You Need), confirmed via arXiv API

Compressive memory

2019-11-13recurrent stateadded — not on the required list
the problem at that moment
Transformer-XL's cache is a FIFO queue: once a state is old enough it falls off the end and is gone entirely. Discarding is a strange choice when the alternative is summarising.
mechanism
Add a second tier. Instead of evicting old memories, compress several of them into one coarser memory and keep that. Recent history stays at full resolution; distant history degrades gracefully rather than vanishing.
what it buys
Much longer effective memory at sublinear cost, and a graceful-degradation curve instead of a cliff. Notably strong on rare words, where the relevant context is often far back.
what it gives up
The compression function has to be trained with its own auxiliary loss, which is extra machinery that can fail quietly. Compressed memories are lossy by construction, so exact retrieval from the distant past is gone — you traded a hard cutoff for a soft blur.
when you would actually pick it
Long documents where distant context is genuinely useful but does not need to be exact. The two-tier idea reappears directly in the compressed-plus-selected branches of NSA.
answers / builds on
Segment-level recurrence (Transformer-XL) (2019-01-09)
Why this card is here. Not in the required list. Included because it is the missing middle between Transformer-XL's discard-the-old cache and the aggressive block compression that DeepSeek's NSA does six years later.
Date source: arXiv v1 (Rae et al., Compressive Transformers), confirmed via arXiv API
https://arxiv.org/abs/1911.05507

Top-k / explicit sparse attention

2019-12-25sparsity
the problem at that moment
Softmax never returns zero. Every irrelevant token still receives some probability mass, which both wastes the budget and dilutes the signal from the tokens that matter.
mechanism
Score everything, then keep only the k highest scores per query and mask the rest to negative infinity before softmax.
what it buys
Concentrates attention mass on genuinely relevant tokens; the paper reports quality improvements, not just savings.
what it gives up
The hidden cost the lesson's widget makes explicit: you still had to compute all n scores in order to find the top k. Selection is not free, and naive top-k saves no compute at all during training — only the weighted sum gets cheaper. It is also non-differentiable at the selection boundary.
when you would actually pick it
When quality from denoising matters more than compute, or as the selection stage inside a method like NSA that has already reduced the candidate set to something cheap to score.
answers / builds on

Sliding-window attention

2020-04-10sparsityshipped 2020-03-31
the problem at that moment
Sparse Transformer's strided pattern was awkward to implement and tuned per modality. Documents mostly need local context plus a few global anchors.
mechanism
Each token attends only to a window of w neighbours — w/2 each side in Longformer, which is bidirectional, or the w tokens behind it in the causal decoder form Mistral popularised. Stack L layers and the effective receptive field is L*w, so information still propagates across the whole document, just indirectly.
what it buys
Cost becomes linear in sequence length, O(n*w). The KV cache is bounded by w rather than by n, so it stops growing. Simple to implement and to reason about.
what it gives up
Exact long-range retrieval. A fact at distance greater than w has to survive being relayed through intermediate layers, and relayed information is lossy — this is why sliding-window models fail 'needle in a haystack' tests at distances a full-attention model handles. Longformer patched it with a handful of global-attention tokens.
when you would actually pick it
Streaming or chat workloads where recent context dominates and you need a bounded cache. Wrong for an agent that must retrieve an exact token from 500K back.
answers / builds on
Sparse Transformer local band (2019-04-23); Image Transformer local attention (arXiv 1802.05751) (2018-02-15)
numbers
theoretical receptive field = layers x window — stated, Beltagy et al. 2020 (stated for the bidirectional case, where each token sees w/2 per side; the causal Mistral variant sees w tokens behind)
Why this card is here. Longformer released its own code before the paper, so 'shipped' here is 10 days negative. What actually took three and a half years was adoption in a decoder: Mistral 7B's weights landed 2023-09-20 (HF API), 1,258 days after Longformer. Longformer was an encoder for documents; Mistral made the sliding window a decoder default. Those are two different events and the timeline shows the first.

Linear attention

2020-06-29recurrent state
the problem at that moment
Sparsity picks which pairs to skip. The other option is to change the algebra so you never form the n x n matrix at all.
mechanism
Replace softmax(QK^T)V with a kernel feature map: phi(Q)(phi(K)^T V), carrying a running sum of phi(k) as the normaliser. Matrix multiplication is associative, so computing K^T V first gives a d x d state instead of an n x n matrix. Decoding becomes a recurrent update of that fixed-size state.
what it buys
O(n) training and O(1) memory per decode step. The KV cache disappears entirely — it is replaced by one fixed-size state matrix regardless of sequence length.
what it gives up
Softmax. And softmax was doing real work: it makes attention selective, so one token can dominate. Without it every write is added into the same state and old contributions are never removed, so the state saturates and recall degrades on long sequences. Quality was well below full attention for years.
when you would actually pick it
Very long sequences where a bounded state is a hard requirement and approximate recall is acceptable. The delta rule and Gated DeltaNet below are both attempts to fix exactly the saturation problem this card creates.
answers / builds on
Scaled dot-product attention (removes its softmax) (2017-06-12); Sparse attention (the other answer to the same bill) (2019-04-23)
numbers
O(n) vs O(n^2); fixed d x d state replaces the KV cache — stated, lesson sections 4-5; widgets s8_widget_3_softmax_removed and s8_widget_4_state_matrix
Date source: arXiv v1 (Katharopoulos et al., Transformers are RNNs), confirmed via arXiv API
https://arxiv.org/abs/2006.16236

2021-2022 — position becomes the problem; exactness gets cheap

The delta rule (fast-weight programmers)

2021-02-22recurrent state
the problem at that moment
Linear attention's state is a running sum. Writing a new key-value pair does not erase whatever was previously stored at that key, so the state accumulates interference until it stops being readable.
mechanism
Before writing, read what the state currently returns for this key, and write only the difference between what you want and what is already there. This is the Widrow-Hoff delta rule from 1960, applied to the attention state.
what it buys
Bounded, non-saturating memory. Updating a key overwrites rather than superimposes, so capacity stops degrading with sequence length.
what it gives up
The update becomes sequential — each step depends on reading the state the previous step wrote — which breaks the parallel training that made Transformers trainable at scale. That is the blocker, and it took three more years to solve.
when you would actually pick it
Whenever you use a linear-attention state at all; the plain running sum is strictly worse. But it was not practical until the parallel formulation below.
answers / builds on
Schmidhuber's fast weight programmers (1992) — the paper's framing (1992); Widrow-Hoff delta rule (1960), pre-arXiv (1960); Linear attention (2020-06-29)
Date source: arXiv v1 (Schlag et al., Linear Transformers Are Secretly Fast Weight Programmers), confirmed via arXiv API
https://arxiv.org/abs/2102.11174

RoPE (rotary position embedding)

2021-04-20positionshipped 2021-03-22
the problem at that moment
Both absolute schemes add position to the input once and hope it survives. What attention actually needs is the relative distance between two tokens, and adding absolute vectors expresses that only indirectly.
mechanism
Do not add anything. Rotate each query and key vector by an angle proportional to its position, in 2D pairs of dimensions at geometrically spaced frequencies. The dot product between a rotated query and a rotated key then depends on position only through the difference m-n. Not every dimension has to be rotated. Many implementations rotate only part of each head and leave the rest unchanged — the lesson flags this as the implementation detail people most often miss, and gives DeepSeek-V4 applying RoPE to only the last 64 dimensions as the example. Unrotated dimensions carry content with no positional signal at all, which is what makes MLA's decoupled RoPE path below possible.
what it buys
Relative position falls out of the algebra exactly, with zero parameters, applied at every attention layer rather than once at the input. Defined at any position.
what it gives up
The frequencies are fixed at training time. Beyond the trained length, low-frequency dimensions enter rotation ranges the model has never interpreted, and quality collapses even though the formula is still defined. Every scaling method below exists to patch this one sentence.
when you would actually pick it
Default for any decoder today. The question is not whether to use RoPE but which scaling scheme you pair with it.
answers / builds on

ALiBi (attention with linear biases)

2021-08-27positionshipped 2021-08-24
the problem at that moment
RoPE, four months old at this point, still degrades past trained length. Maybe encoding position as a vector transformation is the wrong idea entirely.
mechanism
Do not encode position in the vectors at all. Subtract a penalty proportional to distance directly from the attention scores, with a different fixed slope per head.
what it buys
Genuine length extrapolation: train at 1K, run at 2K+ with perplexity holding. No positional parameters, and almost no compute.
what it gives up
A hard recency prior baked into every head. The penalty grows without bound, so a token far enough back is effectively unreachable no matter how relevant it is. This makes ALiBi poor at exact long-range retrieval — the model degrades gracefully rather than remembering.
when you would actually pick it
Long-form generation where relevance really does decay with distance and you value extrapolation over retrieval. Wrong for retrieval-heavy agent workloads. Largely displaced by RoPE plus scaling, which keeps the retrieval ability.
answers / builds on
RoPE (2021-04-20)
Why this card is here. Four months after RoPE. The two are not sequential improvements — they are competing answers to the same failure, proposed almost simultaneously, and the field spent the next two years deciding.

FlashAttention

2022-05-27systemsadded — not on the required listshipped 2022-05-19
the problem at that moment
Everyone had spent three years approximating attention to avoid the n x n matrix. But the real bottleneck was never the FLOPs — it was writing that matrix to GPU high-bandwidth memory and reading it back.
mechanism
Never materialise the score matrix. Tile Q, K and V into SRAM-sized blocks and compute softmax with a running online normaliser, so the full matrix exists only in fast on-chip memory, block by block.
what it buys
Mathematically exact attention — no approximation, no sparsification, unlike the whole 2019-20 wave — at a fraction of the memory traffic, with memory now linear in sequence length rather than quadratic. Long contexts became affordable without giving anything up mathematically.
what it gives up
Nothing mathematically, but it is not bit-identical to a reference kernel: tiling changes the order of floating-point accumulation and FP addition is not associative, so low-order bits differ. The real costs are elsewhere — a hand-written CUDA kernel re-tuned per GPU generation and head dimension, and a constraint on what you can do inside attention, since any variant needing the explicit score matrix cannot use it. Compute is still O(n^2).
when you would actually pick it
Always, if a kernel exists for your hardware. Its real timeline role is that it removed most of the motivation for the 2020 approximation wave.
answers / builds on
Rabe & Staats, Self-attention Does Not Need O(n^2) Memory (arXiv 2112.05682) (2021-12-10); Milakov & Gimelshein, online softmax (arXiv 1805.02867) (2018-05-08); Scaled dot-product attention (keeps it exact) (2017-06-12)
numbers
memory O(n) instead of O(n^2); exact, not approximate — stated, Dao et al. 2022, abstract
Why this card is here. Not in the required list. Included because the timeline is unreadable without it: it explains why Reformer, Linformer, Performer and BigBird all effectively stopped mattering after mid-2022, and why the next wave of savings had to target the cache rather than the score matrix.
Date source: arXiv v1 (Dao et al.), confirmed via arXiv API
https://arxiv.org/abs/2205.14135

Recurrent memory tokens (RMT)

2022-07-14recurrent stateadded — not on the required list
the problem at that moment
Transformer-XL carries the previous segment's whole hidden state across the boundary, which is a lot of memory for information the next segment mostly will not use. What if the model could choose a small summary instead?
mechanism
Add a handful of special memory tokens to the input. The model writes whatever it wants into them by the end of a segment, and they are prepended to the next segment as ordinary tokens. The memory is a learned message the model sends to its future self, and it needs no architecture change at all — just extra tokens.
what it buys
O(1) cross-segment state at a size you choose, learned end-to-end, with no modification to the attention implementation. Scales to very long inputs by chaining segments.
what it gives up
A few tokens is a severe bottleneck — everything the next segment needs must fit through them. Training is sequential across segments and can be unstable, since a bad early write corrupts everything downstream. Exact recall of arbitrary earlier tokens is impossible.
when you would actually pick it
Very long inputs processed in a stream where you can accept a summary rather than exact recall. This is the closest published relative of the course's V4 Memory Stream.

the problem at that moment

mechanism
Multiply RoPE's rotation by a per-dimension exponential decay, so high-frequency components attenuate with distance while low-frequency ones persist.

2023 — the year the bills came due

Grouped-query attention (GQA)

2023-05-22KV cacheshipped 2023-07-18
the problem at that moment
MQA had been available for three and a half years and nobody used it, because collapsing every key head to one cost too much quality. But the cache bill had by then become the dominant serving cost.
mechanism
Interpolate. Give every group of query heads its own shared key/value head. The number of groups *is* the number of KV heads. Llama 2 70B ships 64 query heads over 8 KV heads: 8 groups of 8 query heads each. MQA is the g=1 corner and full MHA is the g=heads corner.
what it buys
Most of MQA's cache saving with most of MHA's quality. Critically, an existing MHA checkpoint can be uptrained into GQA with a few percent of original compute, so nobody had to retrain.
what it gives up
Still a real quality loss versus full MHA, just a smaller one, and it is still linear in sequence length — GQA divides the cache by a constant, it does not change its growth rate. At 1M tokens a constant divisor is not enough.
when you would actually pick it
The default baseline for any decoder you intend to serve. The lesson is explicit that it is the baseline rather than the answer, and MLA below is why.
answers / builds on
MQA (2019-11-06)
numbers
cache divided by heads/groups; still O(n) growth — stated, lesson section 11; widget s8_widget_10_gqa

NTK-aware scaled RoPE

2023-06-26date bounded, not exactcontext scalingshipped 2023-06-26
the problem at that moment
You have a RoPE model trained at 2K and you want 8K tonight, without fine-tuning and without a GPU cluster.
mechanism
Do not interpolate all RoPE frequencies equally. Change the base of the frequency geometric series instead, so low-frequency dimensions get stretched a lot and high-frequency ones barely at all — preserving the fine positional detail that uniform interpolation destroys.
what it buys
Extends context several-fold with zero fine-tuning and minimal perplexity loss. It was usable the day it was posted, which is why adoption was near-immediate.
what it gives up
It is not purely an interpolation — some dimensions get pushed slightly out of bounds, so if you *do* fine-tune, YaRN's own paper reports it underperforms plain Position Interpolation. It was also published without theory or peer review, and the 'NTK' justification is an analogy rather than a derivation.
when you would actually pick it
You need more context right now on a checkpoint you cannot retrain. If you can fine-tune, use YaRN.

Position Interpolation (PI)

2023-06-27context scalingadded — not on the required list
the problem at that moment
Same problem as NTK-aware, approached from a lab instead of a forum: extend a trained RoPE window without retraining from scratch.
mechanism
Divide every position index by the extension factor, so position 8000 in a 2K-trained model is presented as position 2000. Interpolate rather than extrapolate — stay inside the range the model already understands.
what it buys
Extends LLaMA's window to 32,768 tokens — 16x its pretrained 2,048 — with only ~1000 fine-tuning steps, with a stability argument for why interpolation is safer than extrapolation. Outperforms NTK-aware when you do fine-tune.
what it gives up
It squashes all frequencies uniformly, which crushes the high-frequency dimensions that encode fine local distance — so adjacent tokens become harder to tell apart. And unlike NTK-aware it does need fine-tuning to work well.
when you would actually pick it
You can afford a short fine-tune and want the better end state. In practice you would now use YaRN, which is explicitly the combination of this card and the one above.

YaRN

2023-08-31context scalingshipped 2023-08-31
the problem at that moment
Two rival scaling methods existed, each better in a different regime, and neither had a theory of which RoPE dimensions should be treated how.
mechanism
Split RoPE dimensions by wavelength relative to the context window. Dimensions whose wavelength is shorter than the window are left alone; dimensions longer than the window are interpolated; the rest blend — 'NTK-by-parts'. Add a temperature adjustment to attention logits to compensate for the distribution shift.
what it buys
Best of both. Extends context with roughly 10x fewer tokens and 2.5x fewer training steps than PI, and works both with and without fine-tuning.
what it gives up
More hyperparameters — the wavelength boundaries and the temperature all need setting, and the published values are tuned for LLaMA-family models. It is still a post-hoc correction to a positional scheme that was fixed at pretraining time, so it cannot exceed what the base model's attention patterns can support.
when you would actually pick it
The default when you have a RoPE checkpoint and need a longer window. Prefer plain NTK-aware only if you cannot fine-tune at all and need something working tonight; prefer PI only if you want the simplest possible change and can afford the fine-tune. Once you are past roughly 4x extension, or you need retrieval quality to hold across the whole extended window rather than just perplexity, YaRN is the one that still works. It is not the answer if you are pretraining from scratch — then the position scheme itself is the decision.
answers / builds on

Attention sinks / StreamingLLM

2023-09-29sparsityshipped 2023-09-29
the problem at that moment
Sliding-window attention should let you stream forever with a bounded cache. In practice, the moment the first few tokens fall out of the window, perplexity explodes. Nobody knew why.
mechanism
The diagnosis is the contribution: softmax must sum to one, so when no token is genuinely relevant the model dumps the leftover probability mass somewhere — and it learns to dump it on the first few tokens. Evict those and the softmax denominator changes for every subsequent computation. The fix is trivial: always keep the first ~4 tokens in the cache, whatever else you evict. The paper also explains *why* it is the first tokens specifically: in a causal model they are visible to every subsequent token, so they are the most readily trained to absorb leftover mass.
what it buys
Stable streaming over millions of tokens with a fixed cache, from an existing model, with a four-token change and no retraining.
what it gives up
It does not extend the model's context — anything outside the window is still gone. It makes a bounded-memory model stop breaking; it does not make it remember. Keeping the sink tokens also permanently spends four cache slots, and the pretraining-time version of the fix (a dedicated learnable sink token, which is what gpt-oss actually ships) requires retraining rather than being free.
when you would actually pick it
Any long-running streaming deployment on a sliding-window cache. It is close to free, so the question is only whether you have the window in the first place.
answers / builds on
Sliding-window attention (2020-04-10)
numbers
keeping ~4 initial tokens restores stable streaming — stated, Xiao et al. 2023
Why this card is here. gpt-oss-120b (2025-08-04) ships a *learned per-head sink logit*, which is a pretraining-time variant of this idea and required a from-scratch run — 675 days later. That is a different mechanism from the published trick of keeping four tokens, so it is recorded here rather than as this card's release date. An earlier version of this site used it as the release date and drew a conclusion from the gap; see the retraction in Q2-1.

Ring Attention

2023-10-03systemsadded — not on the required list
the problem at that moment
FlashAttention made attention memory linear, but linear in n still exceeds one device's memory when n is a million tokens.
mechanism
Shard the sequence across devices in a ring. Each device holds a block of K and V and passes it to its neighbour while computing, so communication overlaps entirely with computation and no device ever holds the whole sequence.
what it buys
Context length scales with the number of devices, with no approximation whatsoever. This is how million-token exact context becomes physically possible.
what it gives up
It is a distribution strategy, not a cost reduction — total FLOPs are unchanged and still quadratic. You are buying length with hardware. It needs high-bandwidth interconnect, and it does nothing for single-device serving.
when you would actually pick it
Training or batch inference at extreme context on a multi-GPU node. Irrelevant to a single-GPU deployment.
answers / builds on
Blockwise Parallel Transformer (arXiv 2305.19370), named in Ring Attention's own title (2023-05-30); FlashAttention (2022-05-27)
Why this card is here. Not in the required list. Included as the counterexample to the whole timeline: every other card changes the mechanism to pay less; this one keeps the mechanism exact and changes the machine.

Mamba (selective state space)

2023-12-01recurrent stateadded — not on the required list
the problem at that moment
Linear attention and state-space models both give O(1) decoding, but their state update is the same for every token — they cannot choose to ignore an irrelevant token or to remember an important one.
mechanism
Make the state-space parameters functions of the input, so the model selectively decides what enters and what decays out of the state. Recover parallel training with a hardware-aware associative scan.
what it buys
Linear scaling with selective memory and a genuinely competitive quality at moderate scale. It made recurrence a serious option again after five years of Transformer dominance.
what it gives up
Fixed-size state means exact recall of an arbitrary earlier token is impossible in principle — Mamba underperforms attention on tasks requiring verbatim retrieval, which is why the strong 2024-25 models are hybrids rather than pure SSMs.
when you would actually pick it
Long streaming sequences where bounded state matters more than exact recall, or as the recurrent half of a hybrid.

Hybrid depth schedules (interleaved layer types)

2024-02-29compositionadded — not on the required listshipped 2024-03-28
the problem at that moment
Every mechanism above is presented as a choice for the whole network: linear attention OR sparse attention OR full attention. But the two failure modes are complementary. Fixed-state layers are cheap to serve and cannot recall an exact old token; attention layers recall exactly and grow a KV cache per layer. Picking one for all layers means accepting one of those two costs everywhere.
mechanism
Do not pick. Assign different memory systems to different depths and repeat the motif. Most layers carry a cheap fixed state; a minority are attention layers that can read exact earlier tokens. The pattern of layer types is the depth schedule, and it is itself an architectural parameter.
what it buys
Most of attention's exact recall at a fraction of the serving memory, because only the minority attention layers hold a KV cache. It is the design that made long-context recurrent models competitive rather than merely cheap.
what it gives up
A new hyperparameter with a large search space and almost no clean ablation in the literature — the ratio and the placement both matter and are usually inherited rather than measured. Exact recall now depends on how far a token is from the nearest attention layer, which is a strange property to reason about. And it locks two mechanisms into one architecture, so both must be supported by your kernels.
when you would actually pick it
Long-context serving where KV cache is the binding cost and you can afford to pretrain the hybrid. It is the shape most strong 2024-25 long-context models converged on.
answers / builds on
Linear Recurrent Unit (arXiv 2303.06349) — Griffin's stated inspiration for its RG-LRU (2023-03-11); Sliding-window attention (2020-04-10); Mamba (a baseline Griffin compares against, not an antecedent) (2023-12-01)
numbers
LightningLM V4 used the repeating motif DDDGDDDG — six DeltaNet fixed-state layers to two sparse-attention layers — held from the 1.78B seed model to the 120B run — stated, lesson section 13; the lesson is explicit that neighbouring schedules were not cleanly ablated, so this is a successful choice and not a proven optimum

Multi-head latent attention (MLA)

2024-05-07KV cacheshipped 2024-04-22
the problem at that moment
GQA divides the cache by a constant and stops. To go further you have to stop storing keys and values in their original form at all.
mechanism
Project keys and values down into a shared low-rank latent vector and cache only that. At inference the up-projection can be absorbed into the neighbouring weight matrices so the per-head keys and values never need materialising. RoPE needs a separate decoupled path, because rotation does not commute with the low-rank projection. The decoupled RoPE key is cached alongside the latent, so the cache is the latent plus that shared 64-dim key.
what it buys
Cache reduction far beyond GQA — DeepSeek-V2 reports 93.3% KV cache reduction versus DeepSeek 67B, of which about 82 points are the architecture and the rest is 6-bit KV quantization — while reporting quality *better* than MHA rather than merely close to it.
what it gives up
Real architectural complexity: the decoupled RoPE path is a genuine wart, kernels must be written for it, and it is not something you can uptrain an existing GQA checkpoint into. You are committing at pretraining time.
when you would actually pick it
You are pretraining a model you intend to serve at high concurrency and can afford custom kernels. Not a retrofit.
answers / builds on
GQA (2023-05-22); MQA (2019-11-06)
numbers
93.3% KV cache reduction vs DeepSeek 67B — stated, DeepSeek-V2 abstract. Two confounds, and the second is the big one. More importantly the figure is not architecture alone — section 3.2.3 also applies 6-bit KV quantization. DeltaNet, parallelised

2024-06-10recurrent state
the problem at that moment
The delta rule fixed linear attention's memory interference in 2021 and then sat unused for three years, because its sequential update could not be trained at scale.
mechanism
Reformulate the sequence of rank-one delta updates as a WY-style matrix product, which turns the recurrence into chunked matrix multiplications that a GPU can run in parallel.
what it buys
The delta rule's non-saturating memory at trainable speed. This is what turned a 2021 idea into a usable architecture.
what it gives up
Still a fixed-size state, so the recall ceiling of linear attention remains. The chunked formulation adds implementation complexity and a chunk-size hyperparameter that trades parallelism against memory.
when you would actually pick it
As the linear-attention component of a hybrid, where you want better memory than a running sum without paying attention's quadratic cost.
answers / builds on
The delta rule (2021-02-22); Linear attention (2020-06-29)
Why this card is here. Three years and four months between the delta rule and the paper that made it trainable. The idea was never the bottleneck; the parallel formulation was.

Differential Transformer

2024-10-07sparsityadded — not on the required list
the problem at that moment
In long contexts, attention assigns non-trivial probability mass to irrelevant context tokens. The paper calls this attention noise, and it drowns the signal from the token you actually need.
mechanism
Compute two separate softmax attention maps and subtract one from the other, scaled — the same trick as a differential amplifier. Common-mode noise cancels; the genuine signal does not.
what it buys
Measurably sharper attention on long-context retrieval and in-context learning, with reduced activation outliers that help quantisation.
what it gives up
Halves the number of heads to stay parameter- and FLOP-matched, so you get fewer independent attention subspaces for the same budget — the noise cancellation is paid for in head diversity, not in FLOPs. Adds a learned lambda per layer. It does not need a custom kernel — the paper reuses stock FlashAttention with two calls (Appendix A) — though the variant with differing Q/K and V head dimensions does need kernel support. It cannot be applied post-hoc; the model must be pretrained with it.
when you would actually pick it
Pretraining a long-context retrieval-heavy model where attention noise is the observed failure mode.
answers / builds on
Scaled dot-product attention (2017-06-12)

Gated DeltaNet

2024-12-09recurrent state
the problem at that moment
The delta rule gives precise targeted edits to the state. Mamba's gating gives fast wholesale forgetting. Each is bad at the other's job: the delta rule cannot clear the state when the topic changes, and gating cannot surgically update one key.
mechanism
Combine them. A gate controls global decay of the state, while the delta rule handles the targeted key-wise correction, in a single chunked-parallel update.
what it buys
Both erase modes at once, outperforming Mamba2 and plain DeltaNet on language modelling, retrieval and long-context benchmarks at matched scale.
what it gives up
Still a fixed-size state, so verbatim recall from far back remains bounded — the paper's own strongest results come from hybrid variants that reintroduce some real attention layers. More hyperparameters than either parent.
when you would actually pick it
The recurrent layers of a hybrid long-context model in 2025. Not as a full replacement for attention.

DeltaNet, parallelised (2024-06-10); Mamba (2023-12-01)

Native Sparse Attention (NSA)

2025-02-16sparsity
the problem at that moment
Every sparse method so far was bolted onto a model trained densely, and top-k selection still required scoring everything. Sparsity that only applies at inference wastes the training signal, and sparsity that is not hardware-aligned runs slower than the dense kernel it replaced.
mechanism
Three branches per query, combined by a learned gate: coarse compressed blocks summarising the whole sequence, fine-grained tokens from the top-scoring blocks, and a local sliding window. Selection is at block granularity so it maps onto GPU memory access patterns, and the whole thing is trained end-to-end from the start.
what it buys
Sparsity that is native rather than retrofitted, with real measured speedups on 64K sequences and quality matching or beating full attention. Block-level selection makes top-k affordable, because you score blocks rather than tokens.
what it gives up
Architectural commitment at pretraining time and a custom Triton kernel. The three-branch design has more moving parts than a sliding window, and its advantage depends on hardware whose block-access behaviour it was tuned for.
when you would actually pick it
Pretraining a long-context model where you control the kernel stack. This is the current shape of the answer, not a retrofit.
answers / builds on

DeepSeek Sparse Attention (the lightning indexer)

2025-09-29date bounded, not exactsparsityshipped 2025-09-29
the problem at that moment
NSA selects blocks by scoring their compressed summaries, which means the selector and the reader share one representation. That couples two jobs with different requirements: choosing *which* blocks deserve a look should be as cheap as possible, while actually reading them should be as accurate as possible.
mechanism
Split selection from reading. A small lightning indexer scores which earlier tokens are worth attending to; it never produces attention output itself, and its training signal comes from its own loss with its input detached from the main graph. Attention then runs over the top-2048 individual key-value entries per query — token-level, not block-level. Training runs a dense warm-up stage for the indexer first, then a sparse stage.
what it buys
Selection becomes a cheap scoring pass by a small dedicated module rather than full-resolution scoring, so top-k stays affordable at long context. Because selection is per token rather than per block, it keeps fine-grained recall that block selection blurs — DeepSeek's own framing is that this is fine-grained sparse attention for the first time at production scale.
what it gives up
Another trained component that fails on its own terms: an indexer that ranks badly starves the reader, and that failure is silent — you get a fluent answer computed from the wrong context. Top-2048 is a fixed budget, so a query genuinely needing more is capped. It needs the dense warm-up stage and a custom kernel, and it is an architectural commitment, not something you retrofit.
when you would actually pick it
Long-context serving where top-k selection is the bottleneck rather than the attention itself. This is the current production shape of DeepSeek's sparse attention, and the direct answer to the cost NSA's block scoring still pays.
answers / builds on
Native Sparse Attention (2025-02-16); Top-k attention (2019-12-25); Compressive memory (2019-11-13)

DroPE (dropping positional embeddings)

2025-12-13context scaling
the problem at that moment
Every scaling method from PI through YaRN patches the positional function while keeping it. But if over-reliance on explicit position is itself what blocks generalisation to unseen lengths, patching it can only go so far.
mechanism
Remove the positional embeddings entirely after pretraining, then run a short recalibration phase. Positional information was essential as a convergence prior during pretraining; the claim is that it is not required afterwards, and that keeping it is what caps extrapolation.
what it buys
Context extension without the expensive beyond-pretraining-length fine-tuning that every prior method needs.
what it gives up
It is a training-time procedure, not an inference switch — you need the recalibration phase and the compute to run it. And discarding explicit position means relying entirely on the implicit positional information a causal decoder carries, which is a strong claim that will need independent replication.
when you would actually pick it
You have a pretrained checkpoint and can afford a short recalibration run, and you want extension without a long-context fine-tune. Too new to be a default, and the claim that explicit position can simply be removed will need independent replication.
answers / builds on
YaRN (2023-08-31); Position Interpolation (2023-06-27)

Memory Stream (cross-chunk state, LightningLM V4)

2026-08-15date bounded, not exactrecurrent stateadded — not on the required list
the problem at that moment
Split a long document into chunks and chunk 1's attention state is discarded when chunk 2 begins. Without an explicit mechanism, exactly nothing crosses that boundary — the model restarts blind at every chunk.
mechanism
Carry one vector. At the end of a chunk, take its final hidden state and pass it into the next chunk as a single summary of model width. Two rules make it work: it is written with stop-gradient, so the next chunk reads it in the forward pass but training cannot backpropagate through the boundary into every previous chunk; and each token applies it through a small learned gate, updated = current + scale x gate x memory, so a token that needs the old context can use it and an unrelated token can ignore it.
what it buys
O(1) cross-chunk state — one model-width vector after two chunks or two thousand, so the stream never grows with the document. Stop-gradient keeps the training graph bounded, which is what makes it affordable at all. The learned gate means the model decides per token how much history to admit rather than having it forced in.
what it gives up
Severe compression: one vector cannot preserve every sentence of every earlier chunk, so this is a nudge and not a memory. The reported V4 injection is only about 6% of the current embedding magnitude, which is the honest scale of the effect. Stop-gradient also means the model never learns to *write* a memory that will be useful later — it only learns to read whatever happens to be there, the same limitation Transformer-XL has.
when you would actually pick it
Streaming or chunked processing of documents far longer than the window, where a summary nudge across the boundary is worth more than nothing and you cannot afford to grow state. Not a substitute for retrieval when the next chunk needs an exact fact from the last one.
answers / builds on
Recurrent memory tokens (RMT) (2022-07-14); Segment-level recurrence (Transformer-XL) (2019-01-09); Compressive memory (2019-11-13)
